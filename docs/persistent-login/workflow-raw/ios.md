## SUMMARY
iOS auth is centralized in `AuthManager` (@Observable @MainActor singleton, `frontend/apps/ios/Pantopus/Core/Auth/AuthManager.swift`). Tokens are Bearer JWTs from the Express backend (Supabase Auth underneath): `POST /api/users/login`, `/oauth/callback`, `/refresh` all return `{accessToken, refreshToken, expiresIn (3600), expiresAt}` and iOS persists `accessToken`, `refreshToken`, `userId` and a JSON `cachedUser` snapshot into the Keychain via a thin `KeychainStore` wrapper over the KeychainAccess SPM package (service `app.pantopus.ios`, accessibility `.afterFirstUnlockThisDeviceOnly`, `synchronizable(false)`, no access group). Cold start (`PantopusApp.body .task` -> `authManager.restoreSession()`) reads the access token from the Keychain, hydrates `GET /api/users/profile`, and flips `state` to `.signedIn(UserDTO)`; on `.unauthorized` (meaning the silent refresh also failed) it signs out, on transient failures it keeps the session using the cached user. There is no first-launch/reinstall detection: because iOS Keychain items generally survive app deletion, a reinstalled app silently auto-restores the previous session with zero user gesture and no biometric gate, while the biometric app-lock preference (stored per-user in `UserDefaults.standard`) is wiped by the uninstall.

Refresh is purely reactive: `APIClient.executeWithRetry` (and `MultipartUploader.performUpload`) catch a 401 on an authenticated endpoint, call `AuthManager.shared.refreshIfPossible()` (single-flight `Task` so concurrent 401s coalesce into one `POST /api/users/refresh` — the backend rotates refresh tokens and treats replay as `TOKEN_REUSE`), replay once with the rotated token, and call `handleUnauthorized()` -> `signOut()` only if the refresh was `.authRejected` (401 or 400 from /refresh) or the replay still 401s. `.transient` outcomes (5xx, 429, transport, decoding) keep the session and surface a transport error. `expiresIn/expiresAt` are decoded but never read — no proactive/pre-expiry refresh, no BackgroundTasks, no timer. The Socket.IO client connects with the Bearer token and reconnects forever with the token captured at connect; only a successful HTTP refresh reconnects it with a new token.

Sign-out (`AuthManager.signOut()`) is local-only: it deletes the four Keychain keys, clears in-memory state, pending deep links, feed moderation state, disconnects the socket, and resets analytics identity. It does not call any backend logout/revoke endpoint, does not unregister the APNs token, does not purge the 50MB `pantopus-http` URLCache, and there are no session/device-list or "sign out everywhere" endpoints in the iOS networking layer. OAuth ("Continue with Google" / "Continue with Apple") is browser-based via `ASWebAuthenticationSession` (non-ephemeral, callback scheme `pantopus://auth/callback`, per-attempt `app_nonce` CSRF check, then `POST /api/users/oauth/callback` code exchange) — there is no native Sign in with Apple (`ASAuthorizationAppleIDProvider`), no App Attest / DeviceCheck, no Secure Enclave / CryptoKit device key, and no device identifier is sent to the backend (only an `X-Client-Platform: ios-<version>` header).

Biometrics exist only as a UI-level app lock (`AppLockManager` in `Core/Security/AppSecurity.swift`, `LAContext.evaluatePolicy(.deviceOwnerAuthentication)`), a 5-minute-grace `SensitiveScreenGuard` for money surfaces, and a one-time post-login "Enable Face ID?" offer keyed off `AuthManager.lastInteractiveSignInAt`. None of it protects the tokens themselves (no `kSecAccessControl`), and preferences live in `UserDefaults`, not the Keychain. Entitlements declare `applinks:` for pantopus.com/www.pantopus.com/pantopus.app/www.pantopus.app, an app group, and `aps-environment`, but no `webcredentials:` and no `keychain-access-groups`; and `xcodegen generate` (run by `make bootstrap`) regenerates the entitlements file from `project.yml`, which still lists only the `.app` domains — verified in a scratchpad copy that regeneration drops the pantopus.com applinks entries.

## FACTS

## GAPS
- Reinstall behaviour is accidental, not designed: Keychain tokens (afterFirstUnlockThisDeviceOnly, non-synchronizable) survive uninstall on iOS, so a reinstalled app silently auto-restores the full session in `restoreSession()` with no user gesture, while the biometric app-lock preference (UserDefaults) is gone — a previously locked account comes back unlocked. There is no first-launch-after-install marker to detect reinstall and either purge or re-gate ('Continue as X' + biometric).
- No device binding: refresh token is a pure bearer secret with no Secure Enclave key, no App Attest/DeviceCheck, no installation/device id sent on login/refresh, and no trusted-device record — the backend cannot distinguish this device from an exfiltrated token replayed elsewhere (beyond Supabase's rotation/reuse detection).
- Refresh is 401-reactive only; `expiresIn`/`expiresAt` are ignored, so every first request after a long background pays a 401+refresh+replay round-trip, and the socket may connect with an already-expired token; no proactive refresh on foreground/scenePhase .active.
- `signOut()` is local-only: no server-side refresh-token revocation, no APNs token unregistration, no URLCache purge, no 'sign out of all devices' — stolen-device / remote sign-out is not possible from the client, and no sessions/devices endpoints exist in the iOS networking layer.
- Biometric protection is a UI overlay (AppLockManager) decoupled from token storage; tokens are readable without user presence (no `kSecAccessControl` biometryCurrentSet/userPresence item), and the lock preference lives in `UserDefaults.standard` rather than the Keychain, so it neither survives reinstall nor is tamper-resistant.
- No 'Continue as X' or quick-resume UI: `cachedUser` (name/email/avatar) is already in the Keychain but `LoginView`/`PlaceLaunchHost` never offer it; `lastInteractiveSignInAt` is in-memory only.
- Sign in with Apple is not native (browser OAuth via Supabase): no `ASAuthorizationAppleIDProvider.getCredentialState` for silent revocation checks, no native SIWA button, and no `ASAuthorizationPasswordProvider`/passkey path for one-tap re-login after reinstall.
- Associated domains lack `webcredentials:pantopus.com` (and `.app`), so Password AutoFill/passkeys are not domain-associated; login email field uses `.emailAddress` instead of `.username`. Also `project.yml:148-150` is missing the pantopus.com applinks — `make bootstrap`/`xcodegen generate` silently reverts the committed entitlements (verified).
- `restoreSession()` bails to `.signedOut` when only a refresh token exists (access token missing/empty) instead of attempting a refresh; and `refreshSession()` signs out on transient failures, contradicting the `refreshIfPossible` policy (currently only tests call it).
- SocketClient never triggers a refresh on a socket auth failure and reconnects indefinitely with the stale token; no coordination with the HTTP 401 path other than `performRefresh` reconnecting on success.
- TOKEN_REUSE (session invalidated for security) is indistinguishable to the user from a normal expiry — no 'your session was signed out for security' messaging or forced-reauth UX.
- No reinstall/device-change telemetry or trusted-device list UI (Settings has no 'Devices'/'Sessions' surface); no re-auth step-up beyond the 5-minute SensitiveScreenGuard grace on money screens and account deletion.

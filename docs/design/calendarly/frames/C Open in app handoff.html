Open-in-app / booking deep-link hand-off

So an app-having invitee who taps a /book/[slug] or /manage link (or a push) lands cleanly in the native booking flow — with their identity, timezone, and saved details — instead of a degraded signed-out web flow. Two surfaces: a slim web smart-banner over the dimmed public page, and a native continue-in-app interstitial that resolves the link to the right event-type and confirms. Host pillar (Personal sky) on the Continue-in-app primary; neutral resolving chrome. Note: DeepLinkRouter needs new booking routes (pantopus://book/..., /manage).

Native interstitial
A shimmer skeleton card and "Opening your booking" while the deep link maps to the right event-type — never "Loading…".
3 · RESOLVED
Continue in app
Host avatar + pillar dot, an event-type preview card, an identity line, and Continue-in-app + Stay-on-web CTAs.
4 · FAILED
Fallback to web
Warning halo, "We couldn't open this in the app", with a Continue-on-the-web primary reusing Token Accept's fallback routing.
5 · STAY ON WEB
Banner collapses
The banner minimizes to a quiet "Continuing on the web" strip with a confirmation toast; the web flow stays put.
